# 공개 소스 개인정보 검사

`bash gates/public_privacy_gate.sh`는 공개 후보의 개인정보 및 비밀값 패턴을 읽기 전용으로 검사합니다. 문제가 없을 때만 종료코드 0을 반환합니다. 후보 패턴이나 검사하지 못한 대상이 있으면 종료코드 1을 반환합니다. 패턴 일치는 실제 유출 확정이 아니며 검토가 필요합니다. 전체 기능 완료 검사와 공개 승인 절차를 대신하지 않습니다.

검사 범위는 Git에 등록된 현재 파일, 스테이징 영역, 무시되지 않은 새 파일, 모든 참조에서 도달 가능한 커밋의 파일과 기타 도달 가능한 blob입니다. 같은 파일의 과거 내용도 검사합니다. 현재 폴더에서 무시된 환경 파일과 기기·세션·로그 등 비공개 산출물 후보가 발견되어도 실패합니다. 저장소 밖의 홈 폴더는 검색하지 않습니다.

결과에는 범주별 개수, 저장소 기준 상대 경로와 Git 객체 해시만 포함합니다. 탐지한 본문은 출력하지 않습니다. 경로 자체에 민감한 패턴이 있으면 경로 대신 해시를 표시합니다. 검사 과정에서 파일은 변경하지 않습니다.

## 검사 한계와 실패 처리

개인 홈 절대경로, 사설 주소, 인증 문자열, 이메일 후보 및 비공개 산출물 이름을 검사합니다. 알려지지 않은 자격증명 형식과 자연어 개인정보를 완전히 판별하지는 못합니다. 게시 전 별도 검토가 필요합니다.

읽을 수 없는 파일, 8 MiB 초과 객체, 잘린 내용, 변경 중인 파일, 심볼릭 링크, 하위 저장소, 얕은 이력, 대체 Git 객체와 LFS 포인터는 검사 미완료로 처리합니다. 이미지·글꼴·영상·PDF·압축 파일은 내부 내용과 메타데이터를 완전히 확인하지 않으므로 실패합니다. 정상적인 제품 이미지나 글꼴도 자동 허용하지 않습니다. 해당 파일을 배포하려면 별도의 검증 기능을 구현하고 시험해야 합니다.

무시된 일반 파일은 공개 소스 입력으로 취급하지 않습니다. 빌드 결과나 별도 업로드 파일은 이 검사의 통과 범위에 포함되지 않습니다. 공개할 정확한 산출물을 별도 후보 저장소에 넣어 같은 검사를 수행해야 합니다. 참조와 스테이징 영역이 검사 중 변경되면 실패합니다. 검사 이후의 변경은 다시 검사해야 합니다.

## 출처 표시와 시험 예외

LICENSE·COPYING·NOTICE·THIRD_PARTY_NOTICES 계열 파일에서 저작권 표시가 있는 줄의 이메일은 오픈소스 출처 연락처로 보존합니다. 이 예외는 이메일에만 적용하며 인증 문자열이나 개인 경로를 허용하지 않습니다. 파일 전체를 검사에서 제외하지 않습니다. 출처 문서에 실제 개인 연락처를 추가하지 않았는지는 사람이 별도로 검토해야 합니다.

합성 시험 데이터에만 좁은 예외를 사용할 수 있습니다. `--fixture-allowlist <파일>`은 배열 형식의 JSON을 받습니다. 각 항목은 `path`, `sha256`, `category`, `reason`을 가집니다. 경로에는 `tests`, `fixtures`, `__tests__` 중 하나의 디렉터리가 있어야 합니다. 정확한 경로와 파일 내용의 SHA-256 및 탐지 범주가 모두 일치해야 하며 20자 이상의 사유가 필요합니다. 와일드카드와 읽기 실패·바이너리·산출물 예외는 허용하지 않습니다. 내용이 바뀌면 예외가 적용되지 않습니다. 예외 파일도 공개 후보에 포함한다면 동일한 검사를 받습니다.

## 시험

`python3 tools/public-release/test_privacy.py`는 임시 Git 저장소에서 합성 비밀값의 과거 이력 잔존, 현재 파일과 스테이징 내용 차이, 개인 경로·인증 산출물, 출처 연락처 보존, 미지원 파일, 읽기 실패 및 정확한 시험 예외를 검사합니다. 실제 비밀값은 시험에 사용하지 않습니다.

## 정확한 파일 명세를 사용하는 비공개 후보 내보내기

`tools/public-release/export_candidate.py`는 경로·SHA-256·실행 권한을 명시한 JSON만 입력으로 받습니다. 와일드카드, 심볼릭 링크, 변경된 파일, 운영 로그·인증 파일·빌드 캐시는 거부합니다. 출력은 원본 저장소 밖의 새 디렉터리이며 권한은 0700입니다. 원본 이력을 수정하지 않고 새 로컬 Git 저장소에 검토 후보 스냅샷 하나만 기록합니다. 원격 저장소는 등록하지 않으며 공개 업로드 기능은 없습니다.

기본 실행은 런타임·빌드·검증 파일이나 출처·의존성 고지가 하나라도 빠지면 복사 전에 실패합니다. 경로와 범주만 기록한 `missing_required` 목록을 보고서에 저장합니다. `--audit-incomplete`는 검토용 불완전 후보를 생성하지만 종료코드는 계속 1이며 `completeness: FAIL`을 유지합니다. 원본 커밋이 명세와 다르면 실행을 거부합니다.

명세 형식은 `version: 1`, 원본 `source_commit`, `files` 배열입니다. 각 파일은 `path`, `sha256`, `mode`를 가지며 mode는 `100644` 또는 `100755`입니다. 원본 LICENSE를 포함해야 합니다. `EXPORT_PROVENANCE.json`에 원본 커밋과 정확한 파일 해시를 보존합니다. 별도 출처 문서와 의존성 고지도 공개 검토가 끝난 원문을 함께 포함해야 합니다. 저작권 고지를 제거하여 검사를 통과시키면 안 됩니다.

```sh
python3 tools/public-release/export_candidate.py SOURCE MANIFEST NEW_DESTINATION \
  --asset-manifest tools/public-release/verified-fonts.json --report PRIVATE_REPORT
```

후보 검사에 통과하더라도 기능 완전성이나 공개 승인을 뜻하지 않습니다. 검토 중 제외한 파일이 있으면 별도 제외 원장에 사유를 남기고 빌드·테스트·저작권 고지 완전성을 확인해야 합니다. 실제 비밀값과 개인 경로는 후보에서 제외하거나 원본 담당자가 수정한 뒤 새 해시로 다시 내보냅니다. 합성 테스트 예외는 기존의 정확한 경로·해시·범주·검토 사유 규칙을 따르며 자동 생성하지 않습니다.

## 공식 글꼴의 바이트 및 형식 검증

`--asset-manifest tools/public-release/verified-fonts.json`을 지정하면 JetBrains Mono, D2Coding, Noto Sans KR의 지정된 파일만 추가 검증합니다. `appearance-pinned-sources.json`은 공식 저장소의 40자리 고정 커밋, 파일 해시와 크기를 기록합니다. 원본의 가변 브랜치 주소는 검증 근거로 사용하지 않습니다.

검사기는 공식 고정 URL에서 파일과 OFL 라이선스를 다시 받아 로컬 바이트와 비교합니다. 같은 저장소·커밋의 라이선스인지 확인하고, fontTools로 실제 WOFF2/TTF 형식, 필수 테이블과 글리프를 읽습니다. 이름 메타데이터의 개인 경로·인증 문자열·사설 주소도 검사합니다. 내장 SVG·비트맵 및 별도 메타데이터 테이블은 지원하지 않습니다. 파일별 최대 크기는 16 MiB이며, 변경된 해시·출처 응답 실패·누락된 파서가 있으면 실패합니다. 일반 파일의 8 MiB 제한은 유지합니다.

이 기능은 이미지나 임의의 바이너리를 허용하지 않습니다. PNG 로고는 실제 시각 검토와 메타데이터 검증을 결합한 별도 구현이 완료되기 전까지 차단합니다. 글꼴 저작권 연락처는 공식 파일과 정확히 일치하는 라이선스의 저작권 표시 줄에만 적용되며 다른 인증 패턴은 계속 검사합니다.

검증 명령은 `python3 tools/public-release/test_privacy.py`, `python3 tools/public-release/test_export.py`, `python3 tools/public-release/test_assets.py`입니다. 마지막 검사는 로컬 글꼴을 사용하는 합성 출처 응답 테스트이며 실제 공식 URL 비교는 자산 검사를 실행할 때 별도로 수행합니다.

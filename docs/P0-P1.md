# TermWeave P0·P1 보존 기록

## 범위와 상태

TermWeave는 독립 파생 프로젝트입니다. 공개 대상 이름은 `VoidLight00/termweave`입니다. 현재 저장소는 로컬 개발용이며 원격 저장소 생성과 push는 수행하지 않았습니다. 운영 설치본과 기존 세션은 변경하지 않았습니다.

P0는 검토 소스·운영 dist의 제한된 로컬 백업과 별도 복원본의 SHA-256 비교를 수행했습니다. 소스 513개와 dist 96개의 백업·복원 비교에서 불일치는 0개였습니다. 소스와 dist는 공개 후보 저장소 밖에 보관합니다. dist는 공개 소스에 포함하지 않습니다.

P1은 자체 `.git`을 가진 저장소를 만들었습니다. 개발 브랜치는 `development/p0-p1`입니다. `upstream`은 `https://github.com/devswha/herdr-web-ui.git`이며 push 주소는 비활성 값입니다. `origin`은 아직 설정하지 않았습니다. 향후 공개 선택이 계획의 오래된 private 표현보다 우선합니다.

## 정확한 기반과 이력 분리

- upstream: `devswha/herdr-web-ui`
- 기반 커밋: `6bcb9bca4980b5a21b563dafac805a6a6c39ed61`
- 기반 버전: `0.3.45`
- 원본 상태: shallow detached HEAD, 수정 16개, 미추적 소스 51개
- 원저작권: `Copyright (c) 2026 devswha`
- web-ui 라이선스: MIT, 원문 `LICENSE`와 `THIRD_PARTY_NOTICES.md` 유지
- native herdr 라이선스: 공식 저장소 `master/LICENSE` 원문에서 Apache-2.0 확인. native 소스는 이관하지 않았습니다.
- cmux 소스·아이콘은 이관하지 않았습니다. 이 프로젝트는 cmux 또는 herdr의 공식 제휴 제품이 아닙니다.

원본 Git tree에는 evidence와 화면 캡처가 이미 추적되어 있습니다. 삭제 커밋만 추가하면 해당 자료가 이전 이력에 남습니다. 따라서 공개 후보는 검토된 소스 snapshot으로 새 이력을 시작합니다. 기존 설치본의 Git 객체와 이력은 변경하지 않았습니다. 새 저장소에는 원본 Git 객체를 복제하지 않았습니다. 정확한 기반의 안전 소스 462개를 별도 보존하고 로컬 첫 커밋에 기록했습니다. 이는 원본 전체 Git tree와 동일한 tree라고 주장하지 않습니다.

### 향후 3-way 비교 절차

1. 기록된 기반 SHA의 소스 snapshot을 비교 기준으로 사용합니다.
2. 별도의 제한된 작업 경로에 upstream을 가져옵니다. 공개 후보 저장소에 원본 이력을 병합하지 않습니다.
3. upstream 기반 SHA와 새 후보 SHA 사이의 변경을 검토합니다.
4. 기반 소스, TermWeave 소스, 새 upstream 소스를 파일별로 비교합니다.
5. 제외한 캡처·evidence·런타임 자료는 다시 이관하지 않습니다.
6. 검토한 변경만 로컬 커밋으로 적용합니다. 자동 merge·배포는 하지 않습니다.

## 커스텀 파일 대응

수정·미추적 67개를 모두 원장에 기록했습니다. 59개는 원본 SHA-256과 동일하게 이관했습니다. 1개는 개인 실패 스크린샷 저장 경로를 해당 테스트의 임시 경로로 변경했습니다. 7개 개인 운영 smoke 스크립트는 실행 소스로 이관하지 않았습니다. 해당 7개 원본은 제한된 소스 백업에 보존했습니다.

변환한 파일은 `scripts/pane-move-browser.ts`입니다. 변경은 실패 스크린샷 경로뿐이며 런타임 동작은 아직 검증하지 않았습니다.

이관하지 않은 운영 스크립트:

- `scripts/move-live-smoke.ts`
- `scripts/plus-live-smoke.ts`
- `scripts/preview-live-smoke.ts`
- `scripts/session-isolation-live.ts`
- `scripts/spatial-live-smoke.ts`
- `scripts/title-drag-live-smoke.ts`
- `scripts/workspace-navigation-live.ts`

이 스크립트들은 운영 도메인, 개인 인증 파일 읽기, 고정 pane 식별자 또는 운영 세션 변경을 포함합니다. P3에서 합성 데이터·고유 테스트 세션·격리 상태로 다시 설계해야 합니다.

## 공개 후보 제외 정책

`node_modules`, dist, Git 런타임, `.env`, 인증·기기·세션 상태, 실제 대화, evidence, 로그, 화면 캡처는 공개 소스에서 제외합니다. `server/auth.ts`, `server/devices.ts`처럼 인증·상태를 구현하는 소스 파일은 실제 자격증명 파일이 아니므로 유지합니다.

기존 `evidence/**`, `docs/screenshots/**`, `docs/media/**`, `site/media/**`와 캡처 성격의 `site/assets/**`는 제외했습니다. 중립 `grain.png`, `mark-ink.png`, `mark-paper.png`는 유지했지만 자산 출처 검토가 남아 있습니다. 제거된 이미지에 연결되는 기존 README·site 문서는 P5b에서 재작성해야 합니다. 누락된 이미지 참조를 동작 완료로 취급하지 않습니다.

모든 inherited workflow를 `.yml.disabled`로 변경했습니다. CI·Pages·release·remote-bundles는 자동 실행되지 않습니다. 향후 검토한 workflow만 활성화해야 합니다.

## 공개 안전성의 잔여 차단 항목

이 결과는 공개 안전성 통과 판정이 아닙니다. 전체 source에 대해 파일 읽기와 위험 위치 수집을 수행했지만 의미 검토, 바이너리 자산 확인, 라이선스·출처 검증 및 최종 history 검토가 모두 끝난 것은 아닙니다.

- installer/updater/plugin ID/PWA/package 이름과 upstream bundle URL은 아직 원본 값을 유지합니다. 설치·업데이트 실행을 금지합니다.
- inherited README·site에는 제외된 화면 자산 참조가 남습니다.
- 남은 개인 Chrome 경로와 홈 QA 스크립트 의존은 P3에서 제거해야 합니다.
- 사용량 조회 구현에는 provider 인증 읽기 코드가 있습니다. 실제 인증 파일을 복사하지 않았지만 보안·설정 검토가 필요합니다.
- 보존한 바이너리 자산·글꼴의 출처와 독립 브랜드 정책 검토가 남습니다.
- typecheck/build/unit/integration/browser 실행은 이번 단계에서 수행하지 않았습니다. 기능 통과를 주장하지 않습니다.
- 과거 integration 실패와 기존 감사 결과는 최신 PASS 증거가 아닙니다.
- 전체 앱 QA 마스터와 요구사항 검증은 P2 이후 구현 대상입니다. P0·P1 보존 게이트는 제품 기능을 검증하지 않습니다.

## P2·P2b 인계

P2의 기능·요구사항·출처 원장 작업을 로컬에서 시작할 수 있습니다. 공개 릴리스는 계속 BLOCKED입니다.

P2b에 다음 두 사용자 관찰 증상을 별도 수용 기준으로 등록해야 합니다.

1. resize slider로 확장하면 터미널 내용이 잘립니다.
2. 단일 터미널 보기에서도 오른쪽 끝이 잘립니다.

이미지는 원인 확정 증거가 아닙니다. 기존 세션에 명령을 보내지 않고 격리된 합성 fixture에서 원인을 확인해야 합니다. 수정 전 실패와 수정 후 통과를 같은 fixture로 입증해야 합니다.

조사 시작점은 `src/components/PaneTerminal.tsx`, `SplitTerminals.tsx`, `DockDivider.tsx`, 관련 CSS와 `scripts/nested-geometry.ts`, `height-regression.ts`, `split-regression.ts`, `dock-regression.ts`입니다. xterm cols/rows, host/screen/canvas 크기, 폰트 준비, PTY resize, 단일·분할·slider·CJK·상태줄을 함께 비교해야 합니다.

읽기 전용 검토에서 다음 가설을 전달받았습니다. 아직 재현하거나 원인으로 확정하지 않았습니다.

- `DockLayout.css`의 가로 flex body와 `PaneTerminal.css`의 terminal-stack width·flex growth·min-width 제약을 비교합니다. 기존 xterm 너비가 stack 축소를 막는지 body/stack/mount/screen 사각형으로 측정합니다.
- ResizeObserver의 120 ms 지연과 fit·PTY resize를 조사합니다. 일시적 잘림과 500 ms 이후에도 남는 잘림을 구분합니다.
- 공유 PTY geometry와 로컬 interact geometry 차이를 mock geometry 이벤트로 별도 검사합니다. observe·mirror 동작을 보존합니다.

기존 도킹 테스트만으로 마지막 행·마지막 열 가시성을 입증했다고 취급하지 않습니다.

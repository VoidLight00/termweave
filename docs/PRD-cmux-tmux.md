# TermWeave cmux·tmux 기능 확장 PRD

작성일: 2026-10-08. 상태: 구현 계획입니다. 이 문서는 전체 기능 구현 또는 운영 배포 완료를 주장하지 않습니다.

## 제품 목표

사용자는 웹에서 여러 프로젝트와 터미널을 관리하고, 각 터미널의 번호로 정확한 대상을 선택합니다. 터미널 출력과 채팅을 같은 작업 문맥에서 전환합니다. 새로고침, 웹 서버 교체, 원격 연결 장애가 발생해도 실행 중인 작업을 보존합니다.

전체 목표는 고정한 cmux·tmux 소스의 사용자 기능을 대조하고, 구현·실행 증거를 기능별로 확보하는 것입니다. 특정 명령이 호출된다는 사실과 해당 기능의 전체 동작을 지원한다는 사실을 구분합니다. 웹에서 지원할 수 없는 네이티브 동작은 숨기지 않고 별도 연결 프로그램의 요구사항으로 유지합니다.

이번 우선 변경은 폴더 선택과 분리된 접기 화살표, 전체 세션에서 중복되지 않는 터미널 번호, 확인 후 실제 터미널 종료입니다. 화살표로 접으면 프로젝트·폴더 행이 남고 터미널 행만 사라집니다. 접기는 실행을 유지합니다. 닫기·제거는 “터미널을 종료하시겠습니까?” 확인 후 실제 터미널을 종료합니다.

92개와 326개는 정적 추출 수이며 전체 제품 기능 수가 아닙니다. 동적 등록, CLI 별칭, 설정, 운영체제 메뉴와 모바일 기능을 추가 조사합니다. 실행 엔진의 이전 실측값은 tmux 3.5a입니다. 배포마다 실제 버전을 다시 기록합니다. 기준 소스에만 존재하는 기능은 버전 차이로 표시합니다.

cmux 소스는 동작 분석에 사용합니다. GPL/BUSL 코드·자산을 MIT 프로젝트로 복사하지 않습니다. 구현 근거에는 저장소, 리비전, 파일·위치, 라이선스 문서 해시를 남깁니다. upstream 변경은 별도 검토와 시험을 거친 후 기준에 반영합니다.

## 사용자 흐름

1. 사용자는 폴더 행으로 프로젝트를 선택합니다. 옆의 터미널 화살표로 하위 터미널 목록만 펼치거나 접습니다.
2. 펼친 목록에서 터미널별 번호와 상태를 확인합니다. 항목을 선택하면 해당 터미널에 입력 포커스가 이동합니다.
3. 터미널을 분할하거나 채팅 보기로 전환합니다. 다른 터미널의 입력과 임시 작성문은 섞이지 않습니다.
4. 입력이 필요한 작업은 알림으로 확인합니다. 알림을 선택하면 원래 호스트·작업 공간·터미널로 이동합니다.
5. 브라우저 또는 원격 연결을 사용한 작업도 같은 대상 식별 규칙을 적용합니다. 연결이 끊기면 전송 여부가 불확실한 입력을 재전송하지 않습니다.
6. 새 버전으로 새로고침해도 실행 중인 터미널과 인증·기기 연결이 유지됩니다.

## 번호와 접기 동작의 상세 계약

pane은 하나의 터미널 실행 대상을 뜻합니다. 사용자에게 표시하는 번호는 서버가 영구 저장하는 전역 레지스트리에서 부여합니다. 로컬의 모든 세션과 창에 걸쳐 중복되지 않습니다. 세션별 1·2·3이나 화면 배열 순서를 표시 번호로 사용하지 않습니다. 종료한 번호는 다른 터미널에 재사용하지 않습니다. 동시에 생성해도 원자적으로 서로 다른 번호를 부여합니다.

tmux의 창 내 `pane_index`와 서버 범위의 `%pane_id`는 내부 주소 및 상세 정보로 보존합니다. 이 값들은 전역 표시 번호가 아닙니다. 최종 내부 주소에는 호스트·소켓·서버 세대·세션·창·native pane ID를 포함합니다. Herdr의 native pane ID도 변경하지 않습니다. 원격 터미널은 명시적인 기기 이름 공간을 포함합니다. 기기 이름 없이 받은 로컬 “pane 3” 요청은 하나의 대상만 반환해야 합니다.

기존 터미널의 번호는 서버에서 한 번 배정하고 저장합니다. 브라우저마다 다시 배정하지 않습니다. 저장 파일 손상이나 쓰기 실패 시 임의 번호로 계속 진행하지 않고 오류를 표시합니다. 별도 임시 레지스트리에서 재시작·동시 생성·삭제·새 서버 세대 시험을 수행합니다.

닫기·제거 버튼은 단순 보기 숨김으로 처리하지 않습니다. 대상 번호와 이름을 표시한 확인창에서 “터미널을 종료하시겠습니까?”를 확인한 뒤 실제 종료 요청을 보냅니다. 보기 전용 사용자는 종료할 수 없습니다. 작업이 실행 중이어도 확인 전에 종료하지 않습니다. 배포 회귀 시험은 시험용 터미널만 종료합니다.

폴더 행의 선택 버튼과 터미널 목록 화살표는 각각 독립된 버튼입니다. 버튼 안에 버튼을 중첩하지 않습니다. 화살표에는 `aria-expanded`와 제어하는 목록의 ID를 연결합니다. 짧은 접근성 이름은 “터미널 목록 펼치기” 또는 “터미널 목록 접기”입니다. 접힌 상태에서도 폴더명과 터미널 수·작업 상태를 확인할 수 있어야 합니다.

저장값이 없는 기존 작업 공간은 현재 표시를 유지합니다. 사용자가 접은 후에는 해당 선택을 유지합니다. 이 설정은 브라우저별 보기 설정이며 다른 기기에 자동 동기화된다고 표시하지 않습니다. 검색 중 일시적으로 펼친 상태는 영구 설정을 덮어쓰지 않습니다. 활성 터미널이 숨겨져도 선택을 다른 터미널로 바꾸지 않습니다.

## 구조와 구현 원칙

- 기존 인증, PTY, 출력 흐름 제어, 설정 저장과 번역 계층을 재사용합니다. 새 화면마다 동일한 상태 기계를 만들지 않습니다.
- 원격·브라우저·네이티브 기능은 지원 능력을 조회하는 별도 연결 계층으로 나눕니다. 미지원 메서드는 명시적 오류를 반환합니다.
- 명령 인수는 구조화된 값으로 검증합니다. 임의 셸 문자열을 조립하지 않습니다. 입력 전송 결과가 불확실하면 재실행 버튼에 상황을 표시합니다.
- 운영 세션으로 시험하지 않습니다. 각 검사는 자신이 생성한 소켓·프로세스·브라우저 프로필만 정리합니다.
- 한국어 UI는 어절 단위 줄바꿈을 적용합니다. 터미널의 공백·출력 배치는 유지합니다. 320·375·768·1440px와 200% 확대에서 잘림·겹침을 확인합니다.

## 배포 판정과 전체 완료 판정

사용자는 이번 작업의 배포와 새로고침을 명시적으로 요청했습니다. 이 승인은 실행 중인 사용자 세션 삭제나 전체 상태 초기화를 포함하지 않습니다.

안전한 부분 배포는 배포할 기능의 범위, 정확한 산출물, 보존 시험, 복원 시험, 배포 후 확인을 모두 충족해야 합니다. 전체 동등성 판정은 CT-PARITY-01로 별도 유지합니다. 현재 `gates/verify_termweave.sh --deployment`는 전체 동등성 미완료로 실패합니다. 이 문서는 해당 게이트를 수정하거나 우회하지 않습니다.

부분 배포 경로가 없다면 별도 배포 검사와 정책을 먼저 구현하고 검토합니다. 실패하는 전체 검사를 이름만 바꾸거나 삭제하여 배포하지 않습니다. 부분 배포 보고에는 반영한 기능과 아직 미지원인 기능을 함께 표시합니다.

## 완료 증거와 미확정 사항

각 배포에는 소스·산출물 해시, 검사 종료코드, 시험 환경, 변경 요구사항 ID, 실제 화면, 배포 전후 보존 결과와 복원 경로를 남깁니다. 테스트 성공은 배포 성공을 대신하지 않습니다. 사용자 화면의 새 빌드 확인은 서버 파일 교체와 별도로 검사합니다.

브라우저 엔진·네이티브 연결 프로그램의 최종 선택, SSH·mosh 시험 호스트, 실제 AI 제공자별 사용 한도, 실기기 조합은 구현 단계에서 확인해야 합니다. 미확정 상태를 구현 완료로 표시하지 않습니다. 초기 구현은 현재 macOS 호스트와 기존 웹 클라이언트를 기준으로 진행합니다.

## GitHub 공개 조건과 개인정보 보호

사용자는 요청한 목적과 기능을 모두 구현한 뒤 TermWeave를 GitHub에 공개하도록 요청했습니다. 이 순서를 공개 조건으로 유지합니다. 기능이 남은 현재 상태에서는 공개 후보를 준비할 수 있지만 공개 완료를 주장하거나 부분 기능을 전체 완성품으로 발행하지 않습니다. 기존 서비스의 안전한 부분 배포와 GitHub 공개는 별도 판정입니다.

개인 개발 사본을 그대로 공개 저장소로 전환하지 않습니다. 허용한 소스·문서·합성 시험 자료로 별도 후보를 구성합니다. 현재 파일뿐 아니라 공개할 전체 이력과 첨부물을 검사합니다. 지운 파일도 이전 커밋에 남을 수 있으므로 현재 폴더 검사만으로 통과시키지 않습니다. `.env`, 개인 실행 증거, 터미널 출력, 대화, 인증·기기 저장소와 개인 절대경로를 공개 대상에서 제외합니다.

검사 결과에는 노출 값 대신 파일·커밋 위치와 유형만 남깁니다. 오탐 예외에는 사유와 정확한 대상이 있어야 합니다. 비밀값이 발견되면 공개를 중단하고 공개 후보를 다시 구성합니다. 실제 외부 노출이 확인되면 자격증명 교체를 별도 복구 작업으로 다룹니다. 사용자의 기존 저장소 이력을 임의로 삭제하거나 강제 푸시하지 않습니다.

공식 소스와 로고의 출처·라이선스를 확인합니다. 사용 권한이 확인되지 않은 로고는 임의로 가져오지 않습니다. README에는 지원 기능·제한·설치·업데이트·복원·보안 신고 경로를 포함합니다. 독립 설치에서 사용자님의 개인 경로나 실행 중인 Herdr 환경에 의존하지 않는지 확인합니다.

## 지속적인 upstream 반영

upstream은 제품이 참고하거나 의존하는 원본 프로젝트를 뜻합니다. 감시 대상은 공식 cmux·Herdr이며, tmux 엔진의 호환성 차이도 함께 추적합니다. 자동 에이전트는 새 리비전 탐지, 변경 분석, 격리된 수정안, 검사, 후보 버전·변경 기록 작성까지 수행합니다. 이 문서는 도구나 예약 실행이 이미 설치되었다는 뜻이 아닙니다.

관측한 최신 리비전과 검사를 통과한 승인 리비전을 별도로 저장합니다. 새 커밋 발견만으로 버전을 올리거나 기능을 지원한다고 표시하지 않습니다. 라이선스·인증·파괴적 명령·데이터 계약이 바뀌면 자동 승격을 보류하고 검토할 근거를 남깁니다. 실패한 실행에는 재시도 상한과 다음 실행 조건을 기록합니다.

향후 모든 변경의 무조건 자동 배포는 이번 공개 요청에서 추론하지 않습니다. 운영 승격은 해당 배포 정책과 검사 결과에 따라 수행합니다. 자동 에이전트의 완료 조건에는 예약 작업이 실제로 실행된 기록, 고의로 실패시킨 변경이 운영에 반영되지 않은 증거, 이전 후보로 복원한 결과를 포함합니다.
